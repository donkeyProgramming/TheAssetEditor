Music Project Editor

The Music Project Editor gives a culture its own music in Warhammer 3: its battle theme, its campaign map theme, and the campaign's ambient music layers. It is meant to be used by one person, typically whoever maintains an audio mixer mod. Every culture goes into one music project, and building that project produces everything the game needs.

General workflow:
Add a culture => Give its events wavs => Build => Ship the editable pack as a mod

Before you start

  • Load the game's packs. The editor reads the vanilla music scripts and music banks from them.
  • Select an editable pack. The project and everything Build makes are saved into it.
  • Add the wavs you want to use to the editable pack. The editor only picks wavs from the loaded packs, not from disk.
  • The culture's own mod has to set the culture's audio_state in cultures_tables. The music scripts match on that name. The editor does not change any database tables.

Opening a project

Open the editor from the Music Project Editor button on the toolbar, or by opening a .mproj file from the pack file tree.

  • New - starts an empty project, saved to audio\audio_projects\music.mproj in the editable pack.
  • Open - picks an existing .mproj file from the loaded packs.
  • Save - saves the project. Unsaved changes are shown next to the buttons.
  • Build - saves, then builds the mod. See Building.

Adding a culture

Click Add... under Cultures. The Add Culture window asks for:

  • Audio State - the culture's audio_state from cultures_tables, for example Tomb_Kings. battle_music.dat matches on this, and the new event names are built from it in lower case.
  • Subculture key - the full subculture key, for example wh2_dlc09_sc_tmb_tomb_kings. campaign_music.dat matches on this.

Below that is one row per music slot. Tick the slots the culture should be in:

  • Battle theme - the music in a battle with this culture, including prebattle and the results screen.
  • Campaign map theme - the music on the campaign map, and on the campaign victory and defeat screens.
  • Ambient fragments - short phrases layered over the campaign's ambient music.
  • Enemy pulse - percussion, orchestral, ethnic - layers that play when a hostile army of this culture is near you on the campaign map. If skipped, percussion falls back to a generic pulse and the other two are silent.

For each ticked slot you can either give the culture its own music, or tick Borrow an existing culture's audio instead of authoring new and pick a culture. A borrowing culture plays that culture's music in that slot and needs no wavs. This is how vanilla shares one battle theme between Bretonnia, Dwarfs and Empire.

Advanced on each row shows the script code that row will add. Click Add to add the culture.

A culture with several subcultures is added once per subculture, with the same Audio State each time. The battle slots are shared between them; the campaign slots are per subculture.

  • Edit... - runs the window again for the selected culture. Audio already given to the events it keeps is kept.
  • Remove - removes the culture and the audio its events were given.

Giving events their audio

Selecting a culture lists its Events: one per slot that has its own music, with the event name, the State it sets and how much audio it has. Select an event, then use the This culture's audio tab:

  • Add wav... - adds a wav from the loaded packs. With several wavs, the game picks between them.
  • Remove - removes the selected wav.
  • Selecting a wav loads it into the player at the bottom.

The tree on the left decides which wavs play when. Its top entry plays everywhere this event plays. To give one part its own music, select an entry, pick what to Split by and a value, then click Add branch and give the new branch its own wavs. A branch without wavs plays its parent's.

For example, to give a culture separate victory music: select the top entry, split by Battle result, choose win, add the branch, and give it a wav. Every other result keeps playing the top entry's wavs.

What you can split by depends on the slot. It includes Part of the game (pre-battle and results, in battle, campaign map, campaign resolution), Battle result, Battle phase, Battle situation, Key, Campaign result and Faction. The ambient fragments split by Key and Call or response, and the pulses by Key and Variation.

The Vanilla reference tab shows what a vanilla culture has in the selected slot: each file, where it plays and how long it is. Select a file to hear it. This is a guide to how much music a slot normally gets.

Building

Build saves the project, then writes the following into the editable pack:

  • battle_music.dat and campaign_music.dat, rebuilt from the game's own copies with every culture in the project.
  • The wavs, encoded to .wem.
  • Copies of the vanilla music .bnk files, under their vanilla names, with the cultures' music added.
  • The event data .dat.

Things to know:

  • Build always starts from the game's copies. Building twice does not add a culture twice, and removing a culture and building again takes it out.
  • The mod replaces the game's music scripts and music banks, so only one music mod made this way can be active at a time. That is why one project holds every culture.
  • Rebuild after every game update. A built mod contains the game's scripts and banks as they were when it was built. If an update removed something the build relies on, Build stops and lists what is missing instead of making a mod that plays nothing.

Music Script Viewer

The Music Script Viewer on the toolbar shows battle_music.dat or campaign_music.dat as readable code, which helps with understanding what a slot does. Open picks a script from audio\scripts.

  • The function list is on the left. Functions marked ▶ are called directly by the game.
  • The selected function is shown as Pseudocode or as raw Instructions.
  • The Triggers, Vars, StrVars and Strings tabs list the script's tables. Right-click a string that looks like a Wwise event name to search for it in the Audio Explorer.

The viewer is read-only. Build rebuilds both scripts whole from the game's copies, so any edit made directly to a script would be lost.
