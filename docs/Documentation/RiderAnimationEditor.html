Rider Animation Editor

The Rider Animation Editor makes animation sets for mounted riders in Warhammer 3. It never changes a mount's animations. It takes a rider set made for one mount and makes a new set that fits another mount, or converts a rider set between the game's two kinds of riding.

General workflow:
Load the rider and the mount => Pick their animation sets => Fit one slot in the tab you need => Make the whole set => Ship the editable pack

Synchronized and attached riders

Warhammer 3 puts a rider on a mount in one of two ways, and a rider animation is made for one or the other:

  • Synchronized - the rider's animroot moves with the mount's, and the rider sits at saddle height. Example: the Empire horse riders, hu1_empire_hr1_warhorse_hammer on hr1_warhorse.
  • Attached - war beast riders. The rider's animroot stays at the origin on every frame, and the game glues it to an attach bone (ap_, usually ap_riderposition_0) of the mount's tech skeleton. Example: the Kislev horse riders, hu1_wh3_kislev_hr1_warhorse_sword on the same hr1_warhorse.

The tech skeleton is an .anim in a tech folder next to the mount's meshes, for example variantmeshes\wh_variantmodels\hr1\emp\emp_warbeast_horse\tech\emp_warbeast_horse_01.anim. It is the mount's skeleton with the attach bones added.

An attached set is not attached in every slot. Vanilla keeps its deaths (RIDER_DEATH_...) and its matched kills (RIDER_COMBAT_1, RIDER_COMBAT_2 and so on) synchronized. The tool does the same.

Before you start

  • Load the game's packs. The tool reads the animation sets, animations, skeletons and meshes from them.
  • Select an editable pack. Every animation and set the tool makes is saved into it.
  • Open the tool from the Rider Animation Editor button on the toolbar.

Loading the rider and the mount

The Rider and Mount panels above the tabs hold the two models and their animations. Every tab works on what is picked here.

  • Mesh - Browse picks a model. Its skeleton loads with it, and Fragment then lists the animation sets for that skeleton.
  • Fragment - the animation set. In the Rider panel, pick the rider set you start from. In the Mount panel, pick the mount's own set. In the mount change tabs, that is the new mount. ... opens the set in its editor.
  • Slot - picking a slot in the Mount panel loads its animation on the mount, and picks the rider slot of the same name in the Rider panel: RIDER_ and the mount slot, so RUN_1 picks RIDER_RUN_1. You can pick a different rider slot by hand afterwards.

A slot that names an animation that doesn't exist (a few vanilla ones do) loads as no animation. When an animpack is added, changed or removed, the set lists reload by themselves and keep what you picked, so a set the tool has just made shows up in the list.

The animation controls under the viewport play the rider, the mount and the red Preview rider together. The preview is what the current tab makes from the picked slots.

Synchronized Mount Change

Refits a synchronized rider set made for one mount onto another, still synchronized. For example, horse riders onto a cold one. The rider bone (usually the pelvis) is glued to a point on the new mount, on every frame of the new mount's animation for the same slot.

  1. In the Rider panel, load the rider and pick the rider set made for the old mount.
  2. In the Mount panel, load the new mount and pick its set.
  3. Pick a mount slot, for example RUN_1.
  4. Rider bone - the rider bone that is glued to the mount. It is set to root (the pelvis) when the skeleton has one, which every Warhammer 3 rider skeleton does.
  5. Mount vertex - click the mount in the viewport, press F3 for vertex selection, click a vertex on the saddle, then Set. F1 goes back to object selection. If several vertices are selected, the first one is used.

The preview is made as soon as everything is there, and remade whenever a slot, the vertex or a setting changes. Anything still missing is listed in orange under the buttons.

Fit to the new mount

  • Stretch to the mount animation's length - resamples the rider animation to the mount animation's frame count and duration. Off: frames are matched one to one.
  • Plays - how many times the rider animation plays back to back before it's fitted. 1 plays it once.
  • Position offset - moves the rider bone away from the vertex, in metres (X, Y, Z).
  • Rotation offset - turns the rider bone, in degrees (yaw, pitch, roll).
  • Mount scale - scales the mount, and with it where the vertex is.

This slot and the whole set

  • Update preview - makes the preview again. It also updates by itself.
  • Save this slot - saves the picked slot's refitted animation. See Output.
  • Refit the whole rider set to this mount - asks for a name, then makes a new rider set for the new mount. Every RIDER_ animation whose slot the new mount's set has is refitted with these settings and saved. The rest keep their original animation:
    • slots that aren't RIDER_ slots, and RIDER_ slots whose mount slot the new mount doesn't have
    • slots the game plays over the riding motion instead of with a mount animation of their own, so the rider's legs and pelvis in them aren't used: RIDER_SHOOT_READY, RIDER_RELOAD, the transitions between them, RIDER_STAND and RIDER_COMBAT_READY, and every RIDER_CAST_SPELL_, RIDER_MOVING_ATTACK_, RIDER_CELEBRATE_ and RIDER_FIRE_ slot
The pelvis is locked to the vertex on every frame, so the rider's own movement on the saddle is lost. The pelvis keeps its own rotation, with the new saddle's tilt added on top. Because the old saddle's tilt is already in the rider animation, the rotation ends up a few degrees off. Refitting the vanilla Empire set back onto its own horse shows how much this costs: the pelvis loses up to 24 cm of movement in ATTACK_1 (rising in the stirrups), 12 cm in CHARGE and 5 cm in RUN_1, and its rotation is 3 to 8 degrees off on average. To touch an animation up, use Copy the preview for the Keyframe Editor (see Preview).

Attached Mount Change

Moves an attached rider set made for one mount onto another, still attached. The game puts an attached rider on the new mount's attach bone, so the animations carry over as they are. The tab only changes them if you stretch them to the new mount's animations, play them more than once, or offset them. No vertex is needed.

  1. In the Rider panel, load the rider and pick the attached rider set made for the old mount.
  2. In the Mount panel, load the new mount and pick its set.
  3. Pick a mount slot to see it in the preview.
  4. Attach point (optional) - Browse for the new mount's tech skeleton. Only tech folders are listed. The attach bone is picked for you, preferring one with rider in its name. The tech skeleton is only used for the preview: with it, the preview shows the rider on the attach bone, frame by frame, as the game would.

Fit to the new mount

  • Stretch to the mount animation's length - on by default. Resamples each attached rider animation to the new mount animation's frame count and duration. An animation that already has the same length is left alone.
  • Plays - how many times the rider animation plays back to back.
  • Position offset - moves the rider away from the attach bone, in metres (X, Y, Z). Use it if the new mount's attach bone doesn't sit where the rider should.
  • Rotation offset - turns the rider around the attach bone, in degrees (yaw, pitch, roll).

The animroot stays at the origin whatever the settings, so the results are still attached.

This slot and the whole set

  • Save this slot - saves the picked slot's animation with these settings applied.
  • Refit the whole rider set to this mount - asks for a name, then makes a new rider set for the new mount:
    • an attached RIDER_ animation whose slot the new mount's set has is saved with these settings, or kept if they change nothing
    • synchronized slots (the deaths and matched kills) are copied unchanged
    • RIDER_ slots whose mount slot the new mount doesn't have, and slots that aren't RIDER_ slots, are kept

The copied deaths and kills were made for the old mount's height and length. If one looks wrong on the new mount, refit it on its own in the Synchronized Mount Change tab: pick the slot, set a vertex, Save this slot, then point the new set's slot at the saved file in the animation set editor (... next to Fragment).

Whether the game needs an attached rider animation to be as long as the mount animation hasn't been checked in game. If the riders look right without it, turn Stretch off and the set keeps the original animations.

Synchronized ↔ Attached

Converts a rider set, or the picked slot, between synchronized and attached, on the same mount. The conversion needs the mount animation each rider animation plays with, because the attach bone moves with it.

  • Attach point - Browse for the mount's tech skeleton, and check the Attach bone. This is required here. It is shared with Attached Mount Change, so it only has to be picked once. If the tech skeleton doesn't fit the mount's skeleton, the conversion stops and says why.

This slot

  • To attached / To synchronized - converts the picked rider slot's animation against the mount slot's animation. The preview shows the result where the game would put it: an attached result on the attach bone, frame by frame. Slots picked after this are converted the same way, until you switch tabs.
  • Save - saves the converted animation.

Whole set

  • Convert set to attached / Convert set to synchronized - asks for a name, then makes a new rider set. Every RIDER_ animation whose slot the mount's set has is converted against that slot's mount animation. Kept as they are:
    • animations already of the kind you're converting to
    • when converting to attached, the deaths and the matched kills, as in vanilla attached sets
    • slots without a mount slot, and slots that aren't RIDER_ slots
Converting there and back gives the same animation for every bone but the animroot. An attached animation keeps the animroot at the origin, so going to attached loses the synchronized animroot's own movement. Vanilla synchronized animroots wander on their own (up to 2.4 m in the deaths, 1 m in combat idles). The animroot made when going to synchronized follows the mount's animroot instead, which leaves every other bone where it was. On vanilla locomotion slots (stand, walk, run, charge, turn), the Kislev riders converted to synchronized sit within 10 cm of where the Empire riders sit, and the Empire riders converted to attached sit within 10 cm of the Kislev riders.

Output

  • Prefix - new_ by default. A saved animation goes next to the animation it was made from, with the prefix in front of its name. The name box for a new set also starts with it.
  • Animation version - the .anim version to save. Warhammer 3 uses 7.
  • Never overwrite: number the name if it's taken - adds a number when a file of that name exists (new_1_, new_2_...). Off: the existing file is overwritten. Making a whole set never overwrites a file it made earlier in the same run, even with this off, because one rider animation can be refitted against several mount animations.

A new set is saved as animations\database\battle\bin\<name>.animpack, holding one set called <name>. It keeps every slot and variant of the rider set it was made from, with their blend, weight, weapon and meta values, and names the Mount panel's set as its mount. When slots share a rider animation and a mount animation, the new animation is made once and shared too.

After a whole set is made, a results window lists every slot: what was saved, what was kept and why, and warnings, such as an animation that can't be found, or a mount slot the rider set has no animation for.

Preview

  • Show the preview's mesh / Show the preview's skeleton - show or hide the red preview rider.
  • Copy the preview for the Keyframe Editor - copies every frame of the preview to the clipboard. In the Keyframe Editor, Paste under Copy between Keyframe Editors puts them into the animation open there, to touch them up before saving.

Reset

Reset closes the tool and opens an empty one in its place: no models, animations or settings. Anything not saved is lost, so it asks first.
